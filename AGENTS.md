# agentic-harness — project rules

Global orchestration layer for AI coding CLIs, installed per harness:
`devin` -> `%APPDATA%\devin`, `opencode` -> `~/.config/opencode`.
This file is the project's own rules — the *payload* rules that get
installed live under each `harnesses/<name>/payload/`.

## Layout

```
shared/                      # single source of truth for prompt content
├── contract.md              # orchestration contract (REPORT, delegation)
├── global-rules.md          # global AGENTS.md template
├── agents/*.md              # subagent bodies (frontmatter is generated)
├── fragments/<harness>/*.md # per-harness snippets (agent table, launch note)
└── vars.json                # shared placeholders (per-harness values in overlay)
harnesses/<name>/
├── overlay/vars.json        # harness vars: paths, memory mechanism, wording
└── payload/                 # GENERATED — maps 1:1 onto the harness data dir
    ├── AGENTS.md            # built from shared/global-rules.md
    ├── agents/*.md          # built: generated frontmatter + shared body
    ├── skills/*/SKILL.md    # built from shared/contract.md
    ├── hooks/*.py           # devin lifecycle hook scripts (static)
    ├── plugins/*.js         # opencode plugin modules (static)
    └── config.managed.json  # keys merged into the harness config file
build.py                     # renders shared/ + overlay -> payload/  (--check = staleness gate)
install.py                   # installer / --check sync / --harness selector
uninstall.py                 # stamp-driven removal
install.*, uninstall.*       # .cmd/.sh/.ps1 thin shims -> require python
VERSION                      # bumped on every shipped change
```

## Harness notes

- devin: hooks are python scripts wired in `config.json → hooks`
  (placeholders `{{PY}}`, `{{DEVIN_HOME}}`). Primary agent can't be
  replaced -> delegation contract lives in the `orchestrate` skill.
- opencode: hooks are ESM plugins in `plugins/` — v2 modules export a
  default `{id, setup(ctx)}`; guard denies via
  `ctx.permission.hook("evaluate")` + `event.effect="deny"`, memory injects
  via `ctx.session.hook("context")` + `event.system.push(...)`. Primary
  agent IS replaceable -> `agents/orchestrator.md` + `default_agent` in
  managed config. Permissions are V2 `permissions`/`agents` arrays
  (last match wins) — never put v1 `permission` keys in agent frontmatter.

## Rules for working on this repo

- Conversational replies in Spanish; file contents and commits in English.
- NEVER hand-edit files under `harnesses/*/payload/` except `hooks/`,
  `plugins/` and `config.managed.json` — everything else is generated by
  `build.py` from `shared/` + `overlay/`. Edit the source, run
  `python build.py`, commit both. CI fails on stale payloads.
- Bump `VERSION` with every change that affects a payload or installer.
- Conventional commits.
- Installer and devin hook scripts must stay Python 3.8+ compatible,
  stdlib only. Opencode plugins must be dependency-free ESM.
- NEVER commit `credentials.toml`, `.env*`, or `org_id`.
- After changing a payload, verify against a sandbox, never the real home:
  `python tests/test_e2e.py` runs the full install/check/uninstall suite in
  a temp sandbox (11 tests, both harnesses). Manual:
  `python install.py --harness devin --devin-home ./sandbox/devin`
  `python install.py --harness opencode --opencode-home ./sandbox/oc`
  `DEVIN_DATA_DIR=$PWD/sandbox/devin devin doctor` validates devin side;
  `OPENCODE_CONFIG_DIR=$PWD/sandbox/oc opencode debug config` for opencode.
  `--dry-run` prints the plan without writing. `sandbox/` is gitignored.
- Live probes (real CLIs, sandbox homes): `python tests/live_devin.py` and
  `tests/live_opencode.py`. Locally they reuse your real devin creds + the
  devin-proxy at 127.0.0.1:8390; in CI they materialize
  `secrets.DEVIN_CREDENTIALS_TOML` and clone `vars.DEVIN_PROXY_REPO`.
- Entry points: PowerShell one-liner via raw.githubusercontent.com (jsDelivr
  can serve .ps1 as octet-stream, which breaks `irm|iex`); cmd/bash via
  jsDelivr `@main`. install.py downloads commit-pinned files via the API
  (falls back to the legacy repo name while GitHub redirects hold).
- CI (`.github/workflows/ci.yml`) runs install/uninstall smoke tests for
  BOTH harnesses on ubuntu-24.04 + windows-latest — keep it green.
